# 23. User Experience, Navigation & Documentary Mode

This chapter defines how users interact with the application. It specifies workflows rather than implementation details, ensuring a consistent experience across desktop, tablet, mobile, and future VR platforms.

---

# 23.1 UX Philosophy

The interface should never compete with the archaeology.

Users should feel they are **exploring a real site**, not operating a CAD application.

The software continuously balances three priorities:

1. Immersion
2. Scientific transparency
3. Ease of exploration

Whenever these priorities conflict, scientific accuracy takes precedence over visual spectacle.

---

# 23.2 Primary Navigation Modes

The application provides five navigation modes.

| Mode         | Purpose                      |
| ------------ | ---------------------------- |
| Explore      | Free exploration             |
| Guided       | Curated tour                 |
| Research     | Scientific investigation     |
| Documentary  | Passive cinematic experience |
| Presentation | Museum / kiosk mode          |

Switching modes never reloads the scene.

Only UI behavior changes.

# 23.8 Camera Choreography

Camera motion follows cinematic rules.

Avoid

* abrupt rotations
* excessive speed
* unnecessary orbiting

Preferred movements

* slow dolly
* crane
* spline paths
* controlled orbit
* static observation

Camera acceleration should be smooth and physically believable.

# 23.11 Hypothesis Panel

Independent from evidence.

The panel shows multiple hypotheses per object with per-hypothesis confidence.

Example

```text
Hydraulic Reservoir

Confidence: 58% (this object)

Supporting Evidence

Contradicting Evidence

Predictions: 2 confirmed, 1 untested

Compare hypotheses

Acoustic Resonator

Confidence: 31% (this object)

Supporting Evidence

Contradicting Evidence

Predictions: 0 confirmed, 3 untested

Compare hypotheses
```

For each hypothesis the panel shows

* hypothesis name
* confidence per object
* key supporting evidence
* key contradicting evidence
* predictions status
* a "Compare hypotheses" button

Users immediately understand

what supports each hypothesis

and what does not.

See *GIZA - 11 Hypothesis Framework* §11.3 for the hypothesis panel specification.

# 23.18 Comparison Mode

One of the platform's defining capabilities.

Comparison Mode allows users to compare two or more hypotheses side by side.

The comparison presents the following criteria for each hypothesis

* assumptions
* supporting evidence
* contradicting evidence
* predicted observations
* simulation outputs
* unresolved questions
* confidence (per object)
* bibliography

Example

Split Screen

```
Measured Geometry

|

Hydraulic Reservoir
```

or

```
Mainstream

|

Acoustic

|

Hydraulic
```

A side-by-side scene view renders each hypothesis in its own viewport with synchronized cameras. Moving the camera in one viewport updates all others, so that the same object is observed from the same viewpoint under each interpretation.

The purpose is comparison, not advocacy. See *GIZA - 11 Hypothesis Framework* §10.

# 23.26 Error Handling

Missing or incomplete data should never interrupt exploration.

Instead of displaying an error,

the application presents the uncertainty.

Example

```text
Northern Conduit

Continuation Unknown

No verified survey beyond this point.

See competing interpretations.
```

This reinforces the project's philosophy of distinguishing absence of evidence from evidence of absence.

# 23.29 Hypothesis Selector

A hypothesis selector panel lists all installed hypotheses with checkboxes. Users activate one or multiple hypotheses simultaneously.

```
✓ Mainstream Funerary
✓ Hydraulic Reservoir
☐ Acoustic Resonator
☐ Chemical Reactor
☐ Mathematical Reference System
☐ Astronomical Instrument
☐ Unknown Function
```

When a hypothesis is activated or deactivated, the scene updates dynamically: overlays, interpretive objects, simulations, evidence panels, and confidence values update. The geometry does not change.

Multiple hypotheses may be active simultaneously. Each hypothesis's overlays render in its assigned color. Conflicting overlays show both labels with hypothesis attribution.

In Scientific Evidence mode, all hypothesis overlays and interpretive objects are hidden.

See *GIZA - 11 Hypothesis Framework* §11 for the full UI integration specification.
