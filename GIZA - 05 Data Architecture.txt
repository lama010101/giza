
# 1. Data Architecture & Knowledge Engine

This chapter defines the data model that separates **evidence**, **interpretation**, and **visualization**. The objective is that the rendering engine never contains archaeological knowledge directly; it only consumes structured data.

---

# -20. Architectural Philosophy

The application is built around four independent domains:

```text
Evidence
    ↓

Knowledge
    ↓

Theory
    ↓

Visualization
```

Each layer can evolve independently.

For example:

* A new paper updates evidence.
* Confidence scores are recalculated.
* Theory evaluations update automatically.
* The 3D scene immediately reflects the changes without code modifications.


# -13. Theory Schema

This is the heart of the platform.

```json
{
  "id":"THEORY-001",
  "name":"Hydraulic Interpretation",
  "description":"",
  "supports":[],
  "contradicts":[],
  "confidence":58,
  "authors":[],
  "references":[]
}
```

Each theory is evaluated dynamically.

---

# -12. Simulation Schema

Example

```json
{
  "id":"SIM-008",
  "name":"Water Flow",
  "type":"Hydraulic",
  "inputs":[],
  "outputs":[],
  "parameters":{},
  "enabled":false
}
```

Simulations remain independent of theories.

A theory may reference one or more simulations.

# -10. Confidence Propagation

Confidence should not be manually duplicated.

Instead

```text
Evidence

↓

Object Confidence

↓

Theory Confidence

↓

Simulation Confidence
```

Changing one measurement automatically updates every dependent calculation.

---

# -9. Confidence Formula

Initial proposal

```
Object Confidence

=

weighted average

+

source reliability

+

measurement quality

+

consensus factor
```

Later versions may implement Bayesian updating instead of a weighted average.

---

# -8. Contradictory Evidence

Evidence may support multiple theories.

Example

```text
Evidence 34

Supports Theory A

Contradicts Theory B

Neutral toward Theory C
```

The platform never hides contradictory evidence.


# 8. Proposed Enhancement: Evidence Dependency Graph

To strengthen scientific rigor, add explicit dependency tracking between evidence items.

Example:

```text
Laser Scan
      │
      ├── validates Room Dimensions
      │          │
      │          └── supports 3D Geometry
      │                     │
      │                     └── influences Hydraulic Simulation
      │
Photographic Survey
      └── validates Surface Condition
```

This enables users to understand not only *what* supports a theory, but *how* confidence propagates through the system.

---

# 9. Proposed Enhancement: Theory Comparison Matrix

Rather than displaying theories independently, provide a side-by-side comparison against the same evidence set.

| Evidence      | Mainstream |        Hydraulic |       Acoustic |       Hybrid |
| ------------- | ---------: | ---------------: | -------------: | -----------: |
| Sarcophagus   |          ✓ |                ? |              ✗ |            ✓ |
| Water         |     Ritual |       Functional |        Neutral |   Functional |
| North Conduit |   Drainage | Pressure Channel | Resonance Path | Undetermined |

This matrix becomes one of the application's defining research features, allowing transparent comparison without privileging any interpretation.
